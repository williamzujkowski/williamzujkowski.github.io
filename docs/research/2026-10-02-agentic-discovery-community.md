## Substantive counterarguments (HN/Lobsters)
- **#6 auto mode break:** several commenters (incl. a linked Lobsters thread) argue it is *not prompt injection*: the agent's intent was never hijacked; it wrote and ran code in an attacker-controlled cwd. That reframing is arguably stronger: classifier can't judge "safe-looking" code whose import path is hostile. Also: "the dev env won't sandbox easily" (massive IDEs, megarepos).
- **#8 approval game:** prompts' risk labels were disputed in the original thread; artificial timer; zero stakes ("like F1 sim fatality rates"). Use only as directional.
- **#11 ToB VMs:** "QEMU isn't secure and isn't intended to be" — the result says more about QEMU+slirp than about VMs (supports Firecracker recommendation, weakens the headline). Counter-counter: "most people still consider containers sufficient."
- **#12 Green:** "sandbox enough to be safe ⇒ not useful"; opencode permission user: allowing `cat *` allows `cat > file` — command-allowlists don't express read-only.
- **#9 AGENTS.md:** vendor says kill-switch artifact, fixed quickly; others argue reading a local file should never depend on a server flag.
- **#18/#17 OpenAI incidents:** strong anti-anthropomorphism pushback ("lawnmower"); accountability rests with the operator.

## Shortlist (6-8)

1. **Repo-local config executes outside the sandbox** (#1-#4, + GitPython, flatpak-builder CVE-2026-86320). Codex, aider, Gemini CLI, goose all hit within ~2 weeks. Best owned-lab experiment on the list: one synthetic hostile repo (fsmonitor, hooksPath, filters, `.aider.conf.yml`, `.env`), disposable VM, canary file, matrix of harnesses × versions.
2. **Breaking auto mode via stdlib shadowing** (#6 vs #7): vendor numbers (0/720) against an independent 60-80% chain, plus vendor's own "not a security guarantee". Reproducible with a `struct.py` canary.
3. **AGENTS.md silently not loaded under telemetry-off** (#9): a canary-word test of "did my safety instructions load?". Directly relevant to this repo's `CLAUDE.md → @AGENTS.md` setup.
4. **Egress is the boundary** (#10 ZCode, #13/#14 placeholder secrets, #25): measure what a harness sends out; build an allowlist + secret-placeholder proxy in the homelab.
5. **The sandbox ceiling debate** (#11 ToB, #12 Green, #16 Drop): containers < gVisor < VM < Firecracker, and why isolation doesn't fix obedience to injected text.
6. **Human approval is the weakest control** (#8 + #7's 13.6%): exfil missed 3× more than destruction; `npm run` hides payloads.
7. **Dev-box credentials as the blast radius** (#22 DirtyBlanket, #23 arrayref, Miri cache leak): an agent that installs/builds inherits SSH keys, npm tokens, CI secrets. Lab: `preinstall`/`build.rs` canaries against an egress policy.
8. **Real incidents of agents as attackers** (#17-#19): writable shared stores and package registries become C2/exfil channels; real-time monitoring was the missing control.

## Recurring theme
Controls that **report success while not doing the job**: sandbox that falls back to host (DB-GPT), a security scan that skips the executable fields (goose), a "disable snapshots" toggle that does nothing (ZCode), safety instructions skipped silently (AGENTS.md flag), a classifier that the vendor calls "best-effort" yet publishes 0/720, and git config that runs before any permission layer exists. Second theme: **the harness, not the model, is the attack surface**. Most of these exploits never involve the LLM deciding anything.
