# Blog argument shape

Read [repository policy](../../../AGENTS.md) and the
[review contract](../../../docs/skills.md). Read the requested post in full;
resolve repository paths from the root, three directories above this skill.

## Five questions

1. **What is the point?** Quote the load-bearing thesis with a line number. For a
   tutorial or trip report, identify the concrete reader outcome if a thesis
   sentence would be artificial. A project introduction should explain the thing
   before its detailed threat model. If the purpose is absent, say so.
2. **What supports it?** Map each important claim to the relevant citation,
   observed result, working demonstration, counterexample, or clearly labeled
   opinion. Separate cited assertions from independently verified evidence. A
   code block is not a demonstrated result merely because it looks executable;
   an anecdote is not a general benchmark. Citation counts and inline-code counts
   do not measure whether the thesis follows from the evidence.
3. **What kind of post is it?** Identify the primary form: tutorial, explainer,
   experiment report, project story, essay, or position argument. Judge its
   structure against that reader's task. Name the paragraph where the progression
   stalls or changes subject without earning the move.
4. **Does the close follow?** Quote the conclusion and trace it back to the body.
   Flag a broader conclusion than the evidence warrants, a new unsupported
   recommendation, or repeated summaries. Preserve limitations that accurately
   bound a finding; specificity is not corporate hedging.
5. **What would change the conclusion?** For empirical claims, name a plausible
   disconfirming result. For recommendations, identify conditions where another
   choice wins. For explanatory or personal writing, require a clear useful
   contribution rather than forcing every sentence into a scientific hypothesis.
   State the strongest relevant objection and whether the post answers it.

## Result

Report thesis/purpose, evidence map, structural type, close, and objection or
disconfirming condition. Include exact locations and the smallest useful changes.
A missing purpose or unsupported load-bearing conclusion blocks a passing verdict;
counts or formulaic thresholds cannot certify the argument. Record coverage,
verdict, and evidence under the shared contract. Do not invent experiments,
personal history, or references to improve a weak argument.
